# 返品・キャンセルの取り扱いルール

対象読者：新人・後任担当者（LTV/残存率コホート分析クエリ群）
関連クエリ：`01_int_ltv_cohort_base_all` / `02_int_ltv_cohort_base_no_return`（横持ちベースマート）、
`03_mart_ltv_cohort_summary_all` / `04_mart_ltv_cohort_summary_no_return`（月/取引先/コード別まとめ）

本ケース（LTV・残存率コホート分析）の中心的な設計思想を説明するドキュメントです。
このルールを理解しないままSQLを変更すると、獲得件数や残存率の集計結果が意図せず歪む
リスクが高いため、改修前に必ず一読してください。

---

## 1. まず押さえるべき2つのフラグ

このダッシュボード群では、注文に対して主に2種類の「うまくいかなかった」状態を管理しています。

| フラグ名 | 意味 | 具体例 |
|---|---|---|
| `is_cnsl`（CNSLフラグ） | キャンセル。出荷される前に取り消された注文 | 注文直後に顧客が取消依頼、与信エラーなど |
| `is_return_no_refund`（返品_返金保証除くフラグ） | 返金保証ではない返品。一度は出荷されたが、何らかの理由で戻ってきた注文 | 受け取り拒否、長期不在による返送、宛先不明など |

このほかに`is_refund_eligibility`（全額返金フラグ）という項目があり、これは「返金保証制度を使って返品された注文」を表します。**この2つ（`is_return_no_refund`と`is_refund_eligibility`）は別物**であり、この違いが今回の要件の核心です。

---

## 2. 【返品の定義】なぜ2種類を区別するのか

### 2-1. 除外する返品（is_return_no_refund）

**対象**：受け取り拒否、不在による返送など、**返金を伴わない**返品

**なぜ除外するのか**：
これらは「顧客が商品の価値を認めて購入した」という購買行動として成立していません。荷物が届かなかった、受け取ってもらえなかった、というのは実質的に「販売が完了しなかった」ことと同じです。そのため、獲得実績（F1・F2〜F4の各回目のカウント）から除外します。

### 2-2. 除外しない返品（返金保証を使った返品）

**対象**：会社として用意している「全額返金保証制度」を利用して返品された注文

**なぜ獲得件数に含めるのか**：
この場合、顧客は一度きちんと商品を受け取り、実際に試した上で「返金保証を使う」という意思決定をしています。つまり**購買行動そのものは成立している**ため、マーケティング上の「獲得」としては正常にカウントします（その後、制度として返金されたかどうかは、また別の管理項目として追跡します）。

### 2-3. まとめると

```
獲得件数としてカウントする   = 通常購入 + 返金保証を使った返品
獲得件数から除外する        = キャンセル（is_cnsl） + 返金保証でない返品（is_return_no_refund）
```

## 3. F1（初回購入）時点での除外ルール

### 3-1. なぜF1だけ特別なのか

F1（初回購入）は、LTV（顧客生涯価値）分析や残存率分析の**すべての起点（コホートの基準）**になります。ここで「本来は成立していない購入」を紛れ込ませてしまうと、以降のF2・F3・F4の集計、残存率、平均購入間隔など、**分析全体の土台が歪みます**。

そのため、F1を確定させるCTE（両クエリ共通の`purchase_1st`）では、以下の条件で厳密に絞り込みを行っています。

```sql
WHERE
    a.order_no = 1                     -- 1回目の注文であること
  AND a.is_return_no_refund <> 1       -- 返金保証でない返品ではないこと
  AND a.is_cus_deleted_merged <> 1     -- 削除・統合された顧客ではないこと
```

（`is_cnsl`によるキャンセル注文は、そもそも前工程のGUIパラメータ層の絞り込み条件の時点で除外されています）

### 3-2. 具体例で理解する

| ケース | F1として扱われるか |
|---|---|
| Aさんが商品を注文し、正常に受け取った | ○ F1としてカウント |
| Bさんが注文したが、出荷前にキャンセルした | × F1から除外（そもそもF1候補にならない） |
| Cさんが注文し出荷されたが、不在で返送された | × F1から除外 |
| Dさんが注文し、受け取った後に返金保証を使って返品した | ○ F1としてカウント（正常な購入行動として扱う） |

## 4. 「全対象版」と「F2〜返品考慮版」の違い

F1（初回購入）については、上記の通りどちらのバージョンも共通のルールで絞り込みます。**違いが出るのはF2（2回目）以降の扱い方**です。

### 4-1. 全対象版（`01_int_ltv_cohort_base_all` / `03_mart_ltv_cohort_summary_all`）

**コンセプト：返品も含めて「実際に何が起きたか」をそのまま記録する（実績監査モデル）**

- F2〜F4の注文は、返品されたものも**除外せずそのまま**横持ちで結合します。
- その代わり、「2回目_返品(保証除く)フラグ」「3回目_返品(保証除く)フラグ」「4回目_返品(保証除く)フラグ」という列を別途出力し、どの回で返品が発生したかを**後から確認できる**ようにしています。
- 用途：実際の物流・返品の発生状況を監査したいとき、返品を含めた総受注ベースでビジネスの実態を把握したいとき。

### 4-2. F2〜返品考慮版（`02_int_ltv_cohort_base_no_return` / `04_mart_ltv_cohort_summary_no_return`）

**コンセプト：返品された注文はリピートとして数えず、次の正常な注文を繰り上げる（純粋なLTV・残存率モデル）**

- F2以降で返品された注文は、集計から**完全に除外**します。
- 除外した結果、注文の順番に「歯抜け」ができてしまうため、残った正常な注文だけで**改めて1回目・2回目...と番号を振り直し**ます（`order_no_from_f2`という列で管理）。
- 用途：「本当に継続してくれた顧客だけ」を見て、純粋なリピート率・残存率を計算したいとき。

### 4-3. 具体例で違いを見る

Eさんが以下の順で注文したとします。

| 回数 | 状態 |
|---|---|
| F1 | 正常購入 |
| F2 | 正常購入 |
| F3 | 不在で返品（返金保証ではない） |
| F4 | 正常購入 |

**全対象版の場合**：F1〜F4がそのまま4行分の実績として記録され、F3には「返品フラグ=1」が立ちます。

**F2〜返品考慮版の場合**：F3（返品されたもの）は除外されます。残った「F1・F2・（元F4だったもの）」の3件だけを対象に、繰り上げて「1回目・2回目・3回目」と番号が振り直されます。つまり、この版では**Eさんの3回目の注文として、元のF4の注文が扱われます**。

### 4-4. どちらを使うべきか

| 知りたいこと | 使うべき版 |
|---|---|
| 実際に何件出荷され、何件返品されたか（物流実態の把握） | 全対象版 |
| 返品を除いた「本当のリピート顧客」の継続率・LTV | F2〜返品考慮版 |

## 5. 30日ルールとは何か

### 5-1. 何が問題になるのか

「2回目を買っていない顧客」を単純に「離脱した顧客」としてカウントしてしまうと、実は正しくありません。なぜなら、**対象化粧品のおすすめ利用周期（1ヶ月＝約30日）にまだ到達していないだけ**の顧客が大量に混ざってしまうからです。

例えば、F1（初回購入）から10日しか経っていない顧客が「まだ2回目を買っていない」のは当たり前です。この人を「離脱した」とカウントすると、残存率の数字が実態より不当に低く（悪く）見えてしまいます。

### 5-2. ルールの内容

**前回の出荷日から30日が経過して、初めてその顧客を「評価対象」に含める**というルールです。

```sql
-- F2の評価対象になる条件: F1の出荷日から30日以上経過していること
CASE
    WHEN shipment_date_1st < 今日の日付 - 30日 THEN 1   -- 評価対象に含める
    ELSE 0                                              -- まだ評価対象外
END AS is_target_2nd
```

- `is_target_2nd = 0`（評価対象外）の顧客は、まだ判定を下すタイミングではないので、「継続」「離脱」どちらの集計にも数えません。
- `is_target_2nd = 1`（評価対象）になって初めて、「実際に2回目を買ったか(購入フラグ)」「継続中と言えるか(継続フラグ)」を判定します。

### 5-3. 「継続フラグ」の考え方（あわせて理解しておくこと）

30日ルールで評価対象になった顧客について、「継続」とみなす条件は以下の2パターンです。

1. **実際に出荷実績がある**：すでにF2が出荷されている
2. **まだ出荷されていないが、定期契約自体はアクティブ**：定期を解約していない（`is_subsc_active = 1`）ので、次回の出荷予定が組まれている状態

```sql
CASE
    WHEN is_target_2nd = 1 AND is_shipment_2nd = 1  THEN 1  -- 実際に出荷済み
    WHEN is_target_2nd = 1 AND is_shipment_2nd <> 1
     AND is_subsc_active = 1                        THEN 1  -- 未出荷だが定期継続中
    ELSE 0
END AS "2回目_継続フラグ"
```

これにより、「まだ次回出荷日が来ていないだけで、実際には解約していない顧客」を誤って「離脱」に分類してしまう事故を防いでいます。

## 6. 全体像のまとめ図

```
【F1確定時】
  全注文
    │
    ├─ キャンセル(is_cnsl=1)                       → 除外
    ├─ 返品・返金保証でない(is_return_no_refund=1) → 除外
    ├─ 返金保証を使った返品                         → 除外しない（獲得件数に含む）
    │
    └─ 残った注文 = F1として確定（LTV分析の起点）


【F2以降の扱い（版によって分岐）】
  F1確定後の注文
    │
    ├─ 全対象版      → 返品も含めてそのまま記録 ＋ 返品フラグで可視化
    │
    └─ F2返品考慮版  → 返品を除外 → 残った注文を繰り上げ再採番


【評価タイミングの調整（30日ルール）】
  前回出荷日から30日経過していない
    → 「評価対象外」として、継続/離脱どちらにもカウントしない
  前回出荷日から30日経過している
    → 出荷実績あり、または定期継続中なら「継続」、それ以外は「離脱」
```

## 7. よくある質問（Q&A）

**Q1. なぜ「返金保証を使った返品」は除外しないのですか？返品されたのだから実質失敗では？**

A. マーケティング上の「獲得」は、あくまで「顧客が商品を試すという行動を取ったかどうか」で判断しています。返金保証はあらかじめ用意された安心材料であり、それを使って返品するという行為自体が、商品を実際に手に取って評価してもらえたことを意味します。売上や返金実績としては別途管理しますが、「獲得できたかどうか」の指標からは除外しません。

**Q2. F2以降のキャンセル(is_cnsl)はどう扱われますか？**

A. F2〜F4の段階では、そもそも出荷実績があって初めてF2〜F4としてカウントされる設計になっているため、出荷前キャンセルは自然と対象になりません。返品（is_return_no_refund）についてのみ、版によって扱いが分かれます（4章参照）。

**Q3. 30日という日数はどこで変更できますか？**

A. 各クエリ内の`DATEADD(day, -30, ...)`という記述を直接変更する必要があります。対象化粧品の「おすすめ利用周期＝1ヶ月」という業務仕様に基づいた数字なので、変更する際は必ず商品担当・マーケティング担当に確認してください。

**Q4. 「返品考慮版」と「全対象版」で、同じ顧客の「2回目」の中身が違うことがあるのはなぜですか？**

A. 4-3の具体例の通り、返品考慮版では返品された注文が除外され、その後ろの正常な注文が繰り上がって「2回目」として扱われるためです。両方の版を見比べる際は、この「回数のズレ」があり得ることを念頭に置いてください。
